{# The count of open alarms, as a pill on the sidebar's Alarms entry (enerooo-spark's sidebar badge). This partial is the pill ALONE — the element that fetches it lives in layout/nav.html and stays put. That split is the whole point. The first version was one element carrying both `hx-get` and `hx-swap="outerHTML"`, so the response replaced the very element holding the trigger: on the one page that also renders the count server-side (`/alarms`, whose context happens to carry `active_count` and which an include inherits) it looked right, and everywhere else the badge was empty. Those two disagree by design: a tile reads current state, the page reads a log that only has a row if the portal was connected when the Hub published the transition.
