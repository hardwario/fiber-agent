{# Audit log table + pagination (M2-T context contract, P2 v1-style restyle). Context: { entries: [ { kind: "log"|"alarm"|"warning", key, sort_ts, log: the shape below | none, alarm: render::AlarmCtx | none }, ... ] — the log shape: [ { id, ts, event_type: string, username: string|none, user_label: string|none (display form of username, "Jan Novák (admin)" or the bare username, render::person_label), ip: string|none, target: string|none, target_href: string|none, details: string|none, success: bool }, ... ], total: int, limit: int, offset: int, filter: { event_type, username, q, success, since, until — all string|none } } (`ts` assumed a pre-formatted display string, per M1's render.rs convention of formatting timestamps server-side, not in templates). Root id="audit-table" is a plain anchor; there is no SSE/htmx swap target contract here, unlike the alarms table. It used to exist so the page's client-side search box had rows to filter, and the rows carried a `data-search` haystack for it — both gone since the search became a SQL clause (2026-09-14). On a paginated log the old one could only ever search the fifty rows on screen. Prev/next are plain GET forms carrying hidden inputs for the current filter + limit + the recomputed offset, rather than hand-built query strings — lets the browser URL-encode filter values instead of needing minijinja's `urlencode` filter, which Cargo.toml doesn't enable (only the `loader` feature is on).
