{# The interactive four-bound threshold control — v1's ThresholdSlider (viewer/frontend/components/config/ThresholdSlider.tsx) as server-rendered markup over an Alpine component (static/js/portal-thresholds.js). Used by the one limits editor (partials/limits_editor.html), which can load another sensor into it (`load`). Context (all optional, read defensively like the forms that include it): t { critical_low, warning_low, warning_high, critical_high } (each float|none) — the same dict both forms already build slider_unit "°C" | "%" | … — picks the track range (portal-thresholds.js TRACK / INPUT) and suffixes every number slider_value float|none — the sensor's current reading, drawn as v1's black marker so the bounds are set against something real slider_id string — unique on the page; the inputs' `id`, and what their labels point at. The wired form renders one of these per sensor ROW, so a shared id would mislabel every input but the first slider_input_class defaults to "input input-sm", what both existing threshold forms use slider_prefix prepended to each input's `name`. One value for all four bounds; ≥ 0, 0 is off. Left out, no input Layout, top to bottom, as v1 has it: a label row (the four values, nudged apart, a hairline back to the handle when moved), the track with the reading's marker and the four handle bars, the track's range under its two ends, then the four inputs. The four s carry their real `name` attributes and are rendered server-side, NOT by x-for: without Alpine (or before it boots) the form still submits the same six/four fields, it just has no track to drag. That is also why `value` is a plain attribute and `x-model` only takes over once Alpine is up. All geometry that depends on data — handle and label positions, the band gradient, the marker — is inline `style`, bound by Alpine. Tailwind here is only for the static chrome. Two reasons: it is what the numbers demand, and static/css/app.css is a COMMITTED build (`make css`) that carries only the classes present in templates/ when it was last built. A new utility class in this file does nothing until that rebuild lands, which is how the first cut of this partial shipped a track with no width. **An element with `:style` carries NO static `style` attribute.** Alpine's string form of `:style` is `setAttribute('style', value)` — it REPLACES the attribute rather than merging into it (see `setStylesFromString` in static/js/alpine.min.js). The track had `style="height:1.5rem"` beside `:style="background:…"` and the gradient painted over a box 0px tall, which is the invisible bar reported on 2026-09-14. Every static declaration on such an element belongs inside the same bound expression. Blank means unset, as everywhere else in the threshold path.
