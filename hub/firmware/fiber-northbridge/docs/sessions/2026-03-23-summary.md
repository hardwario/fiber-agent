### RF Switch Debugging (Major Issue Resolved)
- **Root cause**: The STM32WL5MOC internal RF switch truth table differs from the generic ST BSP
- Discovered correct truth table from working `fiber-northbridge` firmware:
  - OFF: PC3=0, PC4=0, PC5=0
  - RX: PC3=1, PC4=1, PC5=1 (all HIGH)
  - TX LP: PC3=0, PC4=0, PC5=1 (only PC5 HIGH)
- Zephyr's 2-GPIO driver model couldn't express this 3-GPIO switch
- **Solution**: Patched `sx126x.c` to call board-level weak functions (`board_rf_switch_tx/rx/off`) for `CONFIG_BOARD_STM32WL5MOC`, keeping default behavior for other boards
- `board.c` implements the 3-GPIO control matching fiber-northbridge exactly

- Remaining differences from fiber-northbridge firmware to investigate:
  1. **SMPS drive level management** — 60mA for TX, 40mA for RX (register 0x0923)
  2. **Regulator mode** — DC-DC + LDO (opcode 0x96, param 0x01)
  3. **PA duty cycle tuning** — different duty cycles per power level
  4. **Calibration** — image calibration for 868-870 MHz band
  5. **Ramp time** — fiber-northbridge uses 200us, Zephyr uses 40us

## Key Decisions

3. **Frequency**: Using 869.525 MHz (EU band) matching fiber-northbridge
4. **Sync word**: Private (0x1424) — set automatically by Zephyr LoRa driver
